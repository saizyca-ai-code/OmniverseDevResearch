# Versioning and Staleness Policy

- Every report records creation date and upstream version inspected.
- Use full commit SHAs for source-level investigations where practical.
- Mark a report stale when its source version is no longer suitable or a material upstream change has not been reviewed.
- A newer upstream commit alone does not automatically make a report stale; assess whether relevant symbols or behavior changed.
- Preserve historical conclusions. Add a dated update or superseding report rather than silently rewriting history.
- Upstream update automation should create a review signal, not automatically declare analysis invalid.
